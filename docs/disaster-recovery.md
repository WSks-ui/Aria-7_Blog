# 灾难恢复与回滚

## 部署异常

1. 在 Cloudflare Pages 部署历史中回滚到最近一次已通过生产探针的部署。
2. 确认 `/version.json` 的 `sha` 与目标提交一致，再检查首页、文章、RSS、sitemap 和随机 404。
3. 在 GitHub 修复后重新推送 `main`。不要通过旧版入口或 Workers 部署覆盖新版 Pages。

## 内容误发布

- 尚未发布的文章直接设为 `draft: true`。
- 已发布文章如需撤回，保留文件并设为草稿，再通过正常部署流程发布；这样可避免本地与生产内容目录不一致。

## 密钥与安全事件

安全问题通过仓库私密安全报告通道提交。若怀疑外部服务配置泄露，先撤销或轮换相应凭据，再更新部署环境变量并重新运行生产探针。
